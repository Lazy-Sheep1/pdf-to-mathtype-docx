# 全文复核与修复

验收对象是保存、关闭、重开后的 DOCX，以及由目标 Word 版本新导出的 PDF。建立问题清单：来源区域、交付对象 ID、现象、修复、复查证据。用户要求 PDF 为唯一参照时，不以其他旧 DOCX 补写内容；用户明确提供待修复 DOCX 时，先备份该目标，在副本中局部修复，保留已合格的正文和原生对象。

## 最快的检查次序

1. **全文内容**：先核对段落、标题、引用、数字、标点、表格单元格和图注，再检查阅读顺序与断词。保留逐段映射，跨栏续文不能当成新段落。只比英文字母会漏掉句点、引用编号、单字母和数学符号。
2. **原生公式**：核对清单与 OLE 关系、对象数量、可打开性。实际进入 MathType 编辑代表性对象并保存重开，确认预览同步。结构审计通过不证明公式转录正确。
3. **显示完整**：完整浏览每页，放大每个公式、算法和表格。逐项检查括号上下端、分式线、上横线、根号、矩阵边框、上下标和公式编号。不能只看截图反馈页或自动重叠报告。
4. **重叠与页边**：自动检测正文框/字符碰撞、图片与正文接近、越栏、页底漂移；逐个裁图区分墨迹相交与正常字体框重叠。高公式的上下标与邻近文字框相交可能正常；缺括号却可能完全没有碰撞候选。
5. **清晰度与间距**：确认内容完整后才微调词距、断字、分页和与原稿的视觉接近程度。

每次只修已确认的原因。改动后复查受影响页及其后续分页；全局再核对内容和对象数。已逐项审过且渲染图片未变的区域，可以复用审查结果。

## 根据截图定位根因

先定位截图对应的对象和相邻段落，再在备份副本中检查，避免每次全篇重建。

1. 在 MathType 编辑器里也缺字、缺笔画或公式转录错误：先修原生内容，保存回 Word 并确认预览同步。
2. 原生公式完整，但 Word 或导出 PDF 裁切：检查行距、表格行高、文本框尺寸、对象缩放、基线及缓存预览；修容器后保存、关闭、重开再渲染。
3. 对象周围有重复或漂浮字形：核对公式覆盖区域与保留文本，清除旧文字层或重复对象；不要通过再盖一张图片掩盖残字。
4. 原生内容和容器正确，但当前 Word 的 MathType 缓存仍无法完整显示时，最后才回退为与该原生对象对应的 PDF 高清预览。保持 OLE 可编辑，记录预览来源，并在后续编辑公式后重新同步预览；仅换图不能修复错误的原生公式。

## 常见现象与直接修复

| 现象 | 优先检查 | 修复与验收 |
|---|---|---|
| 单词之间出现箭头 | Word 的格式标记、真实 tab、软换行 | 隐藏标记只改变显示。把人为逐词定位改为自然段和普通空格，清除不必要 tab/软换行；确认文字仍可编辑。 |
| 行内符号低于正文或压住下一行 | OLE 基线、透明预览留白、对象锚点、固定行高 | 以可见字形对齐基线，使用嵌入型对象及自动/最小行距。只改已确认对象，不能按所有图片外框统一上移。 |
| 高括号断裂、上横线缺失 | 公式源区域是否只按字符 bbox 提取 | PDF 的横线可能是独立 drawing，伸展括号可能由多个字形组成。合并完整 glyph、drawing 和必要留白，检查上下端；仅加截图尺寸不能恢复已漏掉的笔画。 |
| 公式内出现漂浮或重复字符 | 源公式替换区域与文字保留区域是否一致 | 完整公式作为一个对象显示，排除该对象覆盖的原始公式残字；独立保留公式编号及相邻正文。重新裁图检查没有带入上一行文字。 |
| 表格横线被文字/公式遮住 | 浮动层级、白底图片、固定行高 | 使用真实 Word 表格、自动行高和单元格内边距；公式留在单元格内，避免白底浮动对象盖住边框。检查跨页表头与行尾。 |
| 图片或公式预览模糊 | 原始资源、实际显示尺寸、Word 图片压缩 | 从 PDF 矢量/原图重新导出，按最终物理尺寸提供足够像素并避免后续压缩。不得放大低清截图冒充提高清晰度。预览替换不得损坏对应原生 OLE。 |
| 两端对齐后词距松散 | 栏宽、语言、自动断字、错误段尾 | 优先调整栏宽/字号与断字，保持自然段和末行正常排版。连续内容被拆成文字框后，框尾会被 Word 当成段末而不对齐；合并段落比逐行拉伸可靠。 |
| 分散对齐后单词像逐字拆开 | 实际末行过短、过度 tracking | 取消全局分散对齐，恢复正文自然重排。必要的局部微调必须核对实际末行，不把短末行拉满整栏。 |

若为保持特别版面使用了定位框，每次调整字距、框宽或断字后都要逐字核对该框尾：句点或引用编号可能被挤到不可见的下一行，而页数与对象数仍正常。保留检查末尾字符的区域清单。用户允许重排时，应优先回到连续段落，减少定位框。

## Word 渲染脚本

```powershell
python -m pip install pywin32
python scripts/word_render.py draft.docx --output work/word.pdf
python scripts/word_render.py draft.docx --output work/word.pdf --force
```

`word_render.py` 仅支持 Windows 桌面 Word。脚本用不可见 `DispatchEx` 实例以只读方式打开文档，在打开前禁用宏和自动链接更新；退出前恢复可能持久化的 Word 更新选项。PDF 先写入临时目录，成功且关闭 Word 后才发布。源 DOCX 不保存；已有 PDF 只有使用 `--force` 才能替换。渲染命令一次处理一个文件，同一会话中的并发调用会报忙，应逐个执行。

这是排版渲染器，不是不可信 Office 文件的安全沙箱。它不主动刷新字段或链接，也不验证 PDF 全文是否完整；这些由上面的内容和视觉复核完成。

COM 调用同步执行，没有可靠的进程内硬超时。外层调度器超时并不表示 Word 已完成或已退出。若卡住，记录正在处理的文件和阶段，检查该独立实例是否等待受保护视图、密码、缺失字体或插件对话框；解决原因后串行重试。脚本在正常返回和 Python 异常时都会尝试关闭文档并退出自己创建的 Word；不要用 `taskkill /IM WINWORD.EXE` 或批量结束 Word，避免关闭用户未保存的文档。强制终止 Python 会绕过清理，须确认并处理遗留的独立实例后再重试。

## 结束条件与说明

- 已发现的遗漏、重复、原生公式错误、公式不全和墨迹重叠全部解决。
- 每页看过；每个公式、每张图、表格和算法有完整显示的证据。
- 修复后的 Word 渲染与原生对象数量、正文清单核对一致，关键句尾与引用完整。
- 交付说明写明实际使用的 Word/MathType 路径、编辑验证范围和未解决的排版妥协；不把“自动检查未检出”写成“绝对无误”。
